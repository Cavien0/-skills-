# 结构—涌现—工程化 Skills 包 v1.0.0

这是一套可迁移到多数支持 Markdown Skills 的 AI Agent / 分析工作流中的技能包。核心目标不是“多做分析”，而是把问题逐步转为可以解释、观测、干预、验证和迭代的模型。

## 目录

```text
SKILL.md                         总控编排 Skill：负责任务路由、门禁、统一质量标准
skills/
  s0-assumption-management/      假设、定义与认知状态
  s1-structure-modeling/         对象、边界、本体与结构
  s2-variable-relations/         变量操作化、关系与因果纪律
  s3-state-dynamics/             状态机、反馈、路径依赖
  s4-emergence-transition/       微观—介观—宏观与阈值变化
  s5-engineering-decomposition/  组件、接口、依赖和工程闭环
  s6-mvp-validation/             最小可交付验证
  s7-observability-falsification/观测、反证与停止规则
  s8-source-intelligence/        信息源检索、证据评估与更新
  s9-retrospective-learning/     复盘、版本化和知识沉淀
templates/                       可复制的表格模板
```

## 使用方法

1. 把总控 `SKILL.md` 作为主 Skill 或编排规则。
2. 按需加载 `skills/<对应目录>/SKILL.md`。不要每次机械地调用所有模块。
3. 用 `templates/` 保存每个项目的结构化记录；同一项目的假设、指标、来源与版本记录应有稳定 ID。
4. 若执行环境不支持多文件 Skills，可将主 `SKILL.md` 放入系统提示词，把需要的子 Skill 按任务追加。
5. 每次交付要区分“模型推演完成”和“现实验证完成”。有计划不代表已执行，有结果不代表有因果证明。

## 首轮执行的最小输入

```text

分析对象与范围：
时间尺度：

暂定假设：
资源与限制：

```

## 优化原则

- 把含混概念先操作化，尤其是用户自创术语。
- 将“涌现/相变”作为需要证明的机制解释，而非装饰词。
- 将信息搜寻从支持性检索扩展为反例、竞争解释、边界条件和工程接口检索。
- 不用一个总分掩盖来源的不同优缺点；记录可靠性、方法、独立性、时效性和可复现性。
- 测试前固定成功、失败、停止和扩大条件，降低事后合理化。
- 用最小充分模型减少过度分析；必要模块才启用。
