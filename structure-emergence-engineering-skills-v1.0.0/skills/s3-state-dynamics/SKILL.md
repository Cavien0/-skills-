# S3：状态动力学与状态机

## 目的
回答“系统现在处于什么状态、在什么条件下改变、变化后是否会返回，以及能在哪里干预”。

## 触发条件
问题涉及过程、阶段变化、策略周期、业务流程、系统运行、风险扩散或动态反馈时。

## 输入
S2变量表、变量关系、时间数据（若有）、目标状态和约束。

## 步骤
1. 定义状态集合；每个状态都应有可区分的判别规则。
2. 识别输入事件、控制参量、约束、反馈、外部冲击和隐藏状态。
3. 为每一条转移写出起始状态、目标状态、触发条件、所需时间、观测信号和干预点。
4. 区分硬阈值、概率性转移、延迟反应和连续变化；无证据时不要虚构精确阈值。
5. 标出正/负反馈、滞后、路径依赖、可逆性和潜在锁定效应。
6. 如有数据，检查转移条件是否在多个样本/时期成立；如无数据，明确模型是待验证机制图。
7. 检查状态遗漏：是否存在能解释失败案例的中间状态或外部条件。
8. 输出状态机图和转移表，并列出最值得验证的转移规则。

## 输出
状态定义、状态机图、转移条件表、干预点和待验证转移规则。

## 验收标准
- 重要转移有清楚条件和观测方式。
- 能区分“发生变化”与“为什么变化”。
- 对滞后、可逆性和路径依赖作出有依据的说明，或明确标为未知。

## 失败判据
状态定义循环；转移只有箭头没有条件；对未来作确定性承诺却没有概率/情景假设；把相关时间顺序误当机制。

## 工具/模板
`templates/state-transition-register.md`；适合时用Mermaid stateDiagram。

## 信息源需求
依赖外部历史数据、技术规范或领域规律时调用S8。模型推演本身不等同于经验验证。
