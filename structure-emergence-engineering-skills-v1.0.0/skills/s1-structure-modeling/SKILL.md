# S1：结构本体建模

## 目的
回答“这个系统由什么构成、如何连接、边界在哪里、什么被排除在外”。

## 触发条件
需要拆解复杂对象、澄清系统边界、比较不同架构，或为变量分析和工程分解建立共同对象模型时。

## 输入
问题定义、S0登记表（若适用）、研究对象、环境、预期用途和约束。

## 步骤
1. 设定模型边界：系统内、系统外、环境、参与者、时间与空间尺度。
2. 定义实体/对象及类别，避免同一名称在不同层级代表不同对象。
3. 为关键对象登记属性、取值范围、身份/生命周期和可观测性。
4. 标出关系类型：组成、依赖、流动、控制、信息交换、竞争、约束或空间连接；不要只画无语义的连线。
5. 识别层级与模块：微观对象、介观模块、宏观系统（仅在有分析价值时划分）。
6. 标注外部接口、输入输出、资源流和边界条件。
7. 检查缺失节点、重复节点、循环依赖和未定义的关系。
8. 以图或表输出，并写出当前结构模型不覆盖哪些现象。

## 输出
结构图/关系表、对象属性表、边界和接口说明、结构缺口列表。

## 验收标准
- 每个关键节点有定义，每条重要边有关系含义。
- 能指出哪些信息跨越系统边界、由谁提供、受什么约束。
- 结构足以支持后续变量登记，而非只有概念标签。

## 失败判据
只有名词清单；关系边没有含义；混淆对象与属性；忽略环境和边界；结构图无法映射到观测或实际工作流程。

## 工具/模板
`templates/structure-variable-register.md` 的“对象与结构”部分；可用Mermaid绘制结构图。

## 信息源需求
若对象边界、标准定义或实际架构依赖外部事实，调用S8；纯内部设计可先给暂定模型，并标注假设。
