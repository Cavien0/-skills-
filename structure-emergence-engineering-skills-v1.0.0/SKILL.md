# 结构—涌现—工程化总控 Skill

## 1. 任务目标

把一个复杂问题转换为**可解释、可观测、可干预、可交付、可证伪、可迭代**的工作系统。默认不追求概念数量，而追求关键机制闭环。

标准链路：

```text
问题与边界
  → S0 假设/认知状态管理
  → S1 对象与结构
  → S2 变量与关系
  → S3 状态与动力学
  → S4 涌现/阈值变化（适用时）
  → S5 工程解构与接口
  → S6 最小验证交付物
  → S7 观测、反证与停止规则
  → S9 复盘、版本化、知识沉淀

S8 信息源情报贯穿所有需要外部证据的环节。
```

这是一条**默认工作链，不是强制流水线**。按问题复杂度调用必要模块；不得为了流程完整而制造无用文档。

## 2. 适用场景与不适用场景

适用：复杂系统解释、机制分析、策略设计、业务流程、AI Agent架构、研究计划、指标体系、可验证假设与MVP。

不适用或需降级：纯创作、简单事实查询、输入信息明显不足且无法合理设定默认值的任务。此时先给简短答案或只完成当前可做的环节，不要强行跑完S0–S9。

## 3. 工作模式

先根据用户目标选择模式；用户明确指定时优先遵从。

- **快速模式**：输出问题边界、核心机制、关键变量、下一步和主要风险。通常调用S0（必要时）、S1–S3的轻量版。
- **分析模式**：建立结构、变量关系、机制链和竞争解释；必要时调用S0–S4、S8。
- **研究模式**：围绕可检验问题开展检索、来源登记、证据比较、反例搜寻；调用S0、S2、S7、S8，其他模块按需启用。
- **工程模式**：把模型变成组件、接口、MVP和验收方案；调用S1–S3、S5–S7、S9。
- **复盘模式**：对照预期与实际，诊断失败层级，记录变更并规划下一轮；调用S7、S9，按需回退其他模块。

若用户未指定模式，选择能够以最低成本交付可靠结果的模式，并在开头简短说明范围，不要把内部路由过程写成冗长说明。

## 4. 全局推理规则

### 4.1 区分认知状态

对关键陈述标记以下状态之一：

- **观察/事实**：有可追溯记录或数据支持；说明时间、范围和来源。
- **推断**：由事实和明确规则推导，写出关键推理桥梁。
- **假设**：暂时接受以便推演，必须说明如何检验或替代。
- **定义/约定**：为分析指定的操作性含义，不冒充自然事实。
- **价值判断/目标**：由用户偏好、规范或决策目标决定，不伪装成经验结论。
- **未知**：当前证据不足；说明其对结论的影响和下一步获取方法。

不得把假设写成事实、把相关关系写成因果关系、把比喻写成机制、把模型输出写成现实验证。

### 4.2 先定义，再推导

术语若无统一含义、属于用户自创概念、或可能有多种解释，先给出可操作定义，并注明“本任务中的定义”。像“文化消视”“中心偏移”之类词语，不得未经定义就当成标准学术术语。

### 4.3 分层与追溯

按需要使用以下故障定位层级：

- L0：前提、假设、问题定义与边界
- L1：对象、结构、边界与接口
- L2：变量、测量与关系
- L3：状态、转移规则与时间尺度
- L4：微观交互、介观结构、宏观模式及涌现解释
- L5：工程组件、资源、部署与执行
- L6：观测、数据质量、验证与判定
- L7：复盘、版本与知识沉淀

层级是故障定位工具，不代表所有系统都必须存在七种彼此独立的实体层。

### 4.4 因果纪律

如声称因果，至少说明：候选机制、时间顺序、替代解释、混杂因素、适用边界，以及可用什么观察或干预区分解释。数据不足时使用“相关/一致/可能机制”，不要写成“导致”。

### 4.5 最小充分原则

优先输出足以支持下一步决策的最小模型。复杂度增加必须带来可说明的收益：提高解释力、预测力、可控性、复现性或交付效率。避免为了显得系统而增加变量、图表、来源或模块。

## 5. 总控执行流程

1. **解析任务**：确认用户要理解、预测、决策、干预还是交付；明确目标输出及使用场景。
2. **设边界**：对象、范围、时间尺度、环境、资源、约束和排除项。
3. **标认知状态**：梳理事实、定义、假设、未知与价值目标；必要时调用S0。
4. **建立最小结构**：调用S1，列出对象、关系、边界和接口。
5. **操作化变量**：调用S2，把关键概念转成可测指标或明确标记为暂不可测。
6. **说明机制与变化**：调用S3；只有存在微观交互形成宏观模式、反馈、阈值或多稳态问题时，才进一步调用S4。
7. **转成工程设计**：用户需要行动或产品时调用S5，定义组件、依赖和接口契约。
8. **选最小实验**：调用S6，优先选择能用较低成本区分竞争解释的测试。
9. **预设证伪和观测**：调用S7；不要等结果出来后才决定成功标准。
10. **外部证据核查**：涉及现实事实、最新资料、技术可行性、标准、法律或高影响决策时调用S8。
11. **复盘与迭代**：获得结果后调用S9，保留历史版本并说明更新原因。
12. **交付**：给结论、依据、适用边界、未知、下一步和可复用的输出物；对未完成的验证明确标示。

## 6. Skill 调用门禁

- **没有边界，不进入高成本建模**：先补齐或明确暂定边界。
- **没有定义，不登记变量**：概念必须能解释、测量或被标为待操作化。
- **没有机制，不直接声称涌现**：至少写出微观规则/交互、聚合路径和宏观模式。
- **没有成功/失败条件，不启动MVP**：测试前固定指标、时间窗与停止规则。
- **没有可追溯证据，不把外部主张标成已核实**：标注待验证并给出检索方案。
- **证据不足时允许停在较低层级**：输出当前能支持的结论和缺口，不用臆测补全链条。

## 7. 标准交付格式

根据任务删减不相关部分，但涉及复杂分析时优先按以下顺序组织：

1. **问题定义与结论范围**：要解决什么，不解决什么。
2. **关键假设与认知状态**：哪些已知、推断、假设、未知。
3. **结构模型**：对象、边界、连接关系、外部接口。
4. **变量与机制**：指标、关系、反馈、替代解释。
5. **状态转移/涌现条件**：仅在适用时给出阈值与条件。
6. **干预点与工程组件**：可做什么、依赖什么、资源是多少。
7. **MVP与验证设计**：测试、指标、时间盒、成本上限。
8. **失败判据与风险**：什么结果会推翻或降低对当前解释的信心。
9. **证据与来源**：对外部事实给来源、日期、质量及局限。
10. **下一轮决策**：继续、修改、扩大、暂停或停止，并说明触发条件。

## 8. 默认输出物

按任务选择，不要求全部生成：

- 假设/断言登记表
- 结构本体图或对象关系表
- 变量登记表与因果/反馈图
- 状态转移表
- 涌现机制与阈值条件表
- 工程组件清单与接口契约
- MVP验证卡
- 观测与失败判据表
- 来源登记表与检索日志
- 复盘与版本变更记录

模板位于 `templates/`。独立Skill位于 `skills/`。

## 9. 质量门槛

一份结果至少满足以下要求才可交付为“已完成分析”：

- 关键术语有定义；范围和假设可见。
- 核心结论能追溯到数据、来源或明确推导。
- 主要变量有意义，测量方式可行，或清楚标出测量缺口。
- 机制解释不是循环定义，也不是单纯贴标签。
- 存在竞争解释、反例或明确说明尚未检验。
- 若承诺工程行动，有交付物、验收和失败判据。
- 不确定性、限制和下一步决策清楚。

## 10. 禁止的伪完成

- 只有概念图，没有机制、数据或决策用途。
- 只有变量列表，没有定义、测量、关系或用途。
- 只列支持证据，不找反例、边界或替代解释。
- 以“涌现”“复杂性”“系统性”等词汇代替因果链。
- 只写“持续优化”，没有变更依据和版本记录。
- 把单一来源、模型生成内容或未经复现的结果包装成事实。
- 为了满足模板而输出超出证据能力的精确阈值或伪量化评分。
