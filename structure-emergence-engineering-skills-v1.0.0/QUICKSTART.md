# 快速启动：把 Skills 用起来

## 一、复制即用的启动提示

将以下内容发送给支持文件读取的 AI Agent，或放在项目的首条指令中：

```text
请使用“结构—涌现—工程化 Skills 包”完成本任务。
先读取总控 SKILL.md，再按任务需要选择性读取 S0–S9，不要机械地调用全部模块。
请区分事实、推断、假设、定义和未知；先定义术语和问题边界，再建立结构、变量和机制。
若使用“涌现”“相变”或因果语言，请给出可检验机制、适用条件、替代解释和反证条件。
凡涉及现实外部事实、最新信息或技术可行性，使用 S8 追溯来源，并主动检索反例、限制和失败案例。
```

## 二、建议的 7 天 MVP 路径

这是一条适用于初次搭建一个具体项目模型的示例节奏，不是僵化规定。每日任务可以合并，研究任务也可能需要更长时间。

### 第 1 天：把问题锁定
完成问题边界、使用场景和S0断言登记。写清要解释/预测/改变什么，以及明确不处理什么。建立S8关键词矩阵，并先查清核心术语。

**交付物：** 一页问题定义 + 假设/断言登记表。

### 第 2 天：画出最小结构
完成S1，只保留与当前决策直接有关的对象、边界、关系和接口。每条连线写明含义。

**交付物：** 一张结构图 + 对象属性表。

### 第 3 天：变量操作化
完成S2，选出最少但足以支持当前判断的变量，记录定义、单位/范围、测量方式、数据来源和误差风险。

**交付物：** 变量登记表 + 关系/因果假设图。

### 第 4 天：描述状态变化
完成S3，挑选一条关键状态转移，定义转移条件、时间窗、反馈、观测信号和干预点。无依据的阈值先标为“待估计”。

**交付物：** 一条状态转移卡 + 状态机草图。

### 第 5 天：检验机制与信息源
仅在问题确实涉及跨层级模式或临界变化时启用S4。并行运行S8：找支持证据、反例、竞争解释、适用边界和工程接口。

**交付物：** 机制图 + 证据地图；若不适用涌现分析，则记录跳过理由。

### 第 6 天：把模型转成可执行方案
完成S5，确定最小组件、数据/控制流、接口、依赖、资源上限和故障降级方案；选择能区分竞争解释的最小测试。

**交付物：** 组件清单 + MVP验证卡（事前判据已填写）。

### 第 7 天：执行、判定、复盘
运行MVP（若客观上无法在当天执行，明确标记为“待执行”，不得伪装已验证）。按S7检查数据质量与反证条件，再用S9记录结果、版本和下一步。

**交付物：** 结果/验证报告 + 复盘记录 + 下一轮决策。

## 三、状态转移验证卡的最小格式

| 字段 | 内容 |
|---|---|
| 问题与目标 | 本轮具体想判断什么 |
| 起始状态 → 目标状态 | 两个状态的可区分定义 |
| 触发条件/机制 | 哪些变量在什么条件下通过什么机制起作用 |
| 关键观测指标 | 指标、来源、时间窗、误差 |
| 竞争解释 | 至少一个可以解释同一现象的替代机制 |
| 预设成功标准 | 什么结果会增加对当前解释的信心 |
| 预设反证条件 | 什么结果会削弱或推翻当前解释 |
| 无结论条件 | 哪些数据质量/样本问题会导致本轮不能判断 |
| 干预点 | 能改变什么；哪些因素不可控 |
| 资源/停止规则 | 成本上限、时间盒和停止条件 |
| 结果与边界 | 实际观测；能说明什么，不能说明什么 |
| 来源与版本 | 数据、来源、模型/提示版本、记录日期 |

## 四、快速判断本轮是否值得调用全部模块

- 只需要整理一个概念：先定义概念并给边界，不跑完整链路。
- 需要解释复杂现象：优先S0–S4和S8。
- 需要设计工具/系统：优先S1–S3、S5–S7。
- 需要基于现实资料判断：优先S0、S2、S7、S8，其他按需启用。
- 已有测试结果：优先S7、S9，再针对具体缺陷回退相应模块。

## 五、首轮验收清单

- [ ] 关键术语已定义，含混词没有伪装成标准概念。
- [ ] 事实、推断、假设、定义、未知分开。
- [ ] 结构中的关系有明确语义。
- [ ] 关键变量有操作定义和测量/验证路径。
- [ ] 因果主张有机制、竞争解释和反证方式。
- [ ] 如使用“涌现/相变”，有机制和适用条件，不只是贴标签。
- [ ] 工程任务有组件、接口、资源与降级路径。
- [ ] MVP判据在测试前写明，并区分失败与无结论。
- [ ] 外部关键断言可以追溯，且检索过反例和限制。
- [ ] 复盘记录了版本差异与下一步决策。
